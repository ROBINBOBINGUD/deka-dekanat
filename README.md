# Дека — цифровой деканат в кармане

Прототип личного кабинета студента для конкурса **MGIMO×AI Challenge**, номинация «Вайб-кодинг», задание «Цифровой деканат будущего». Адаптирован под ДПИ НГТУ (Дзержинск).

**Живой стенд:** https://deka-ityorkedj.msk1.amvera.tech (хостинг в России, открывается без VPN). **Описание процесса создания:** https://deka-ityorkedj.msk1.amvera.tech/opisanie.pdf

> Это концепт для конкурса, а не официальный сервис вуза. Все студенты, преподаватели, оценки и номера зачёток вымышленные. Логотип — собственный.

Код написан ИИ-ассистентами (Claude Code, Codex) под управлением человека. Как шла работа — в [docs/Описание.pdf](docs/Описание.pdf) и в журнале [docs/process-log.md](docs/process-log.md).

## Что умеет

| Раздел | Что внутри |
|---|---|
| Сегодня | ближайшая пара и аудитория, лента дня, изменения расписания на неделю, горящие сроки, статус заявок, вывод «как дела с учёбой», объявления |
| Расписание | день и неделя, числитель и знаменатель, аудитория и преподаватель; отмены, замены и переносы выделены маркером |
| Учёба | одна фраза-вывод (всё хорошо, нужно внимание, есть долг), баллы по контрольным точкам, прогноз итоговой оценки, зачётка по семестрам, расписание сессии |
| Заявки | 7 видов (справки, пересдача, продление сессии, матпомощь, дубликат, вопрос в деканат), статус по шагам, переписка с деканатом, электронная справка с кодом проверки |
| Уведомления | объявления деканата, статусы заявок, изменения расписания, напоминания о сроках за 3 дня |
| Профиль | ФИО, факультет, направление, курс, группа, зачётка; смена пароля |
| Кабинет сотрудника | очередь заявок, смена статуса с комментарием, ответ студенту, объявления для группы, факультета или всех, отмена и перенос пар |
| Проверка справки | публичная страница `/verify/<код>`: подтверждает подлинность, не раскрывая группу, зачётку и оценки |

Разделы связаны: долг в зачётке ведёт к заявлению на пересдачу с уже выбранной дисциплиной; смена статуса заявки сотрудником создаёт уведомление студенту; отмена пары сразу видна в расписании и на «Сегодня».

## Тестовые аккаунты

Логины: `student1` (2 курс, ИТ), `student2` (3 курс, химическая технология, есть долг), `dekanat` (сотрудник).

- **Стенд для жюри.** Пароли указаны в комментарии к работе. В открытом репозитории их нет: иначе любой читатель кода мог бы войти под сотрудником и испортить стенд перед показом (это заметил Codex на ревью безопасности).
- **Локальный запуск.** Пароли лежат в `seed/demo-accounts.json`; свои можно сгенерировать командой `node scripts/gen-demo-accounts.mjs --force`.

Смена пароля в демо-аккаунтах отключена, чтобы вход нельзя было «угнать».

## Запуск

Нужен Node.js 22.13 или новее (проверено на 24). База данных — встроенный в Node SQLite, ставить ничего не нужно.

```bash
npm install
npm start          # http://localhost:3000, при первом запуске база заполняется сама
npm test           # 37 тестов: разделение данных, вход, заявки, кабинет сотрудника, защита от подбора
npm run seed       # пересоздать базу из seed/data.json
```

Настройки — переменные окружения, см. [.env.example](.env.example). Секретов у прототипа нет.

Проверка в настоящем браузере (нужен Python и `pip install playwright`, затем `playwright install chromium`):

```bash
python scripts/e2e.py http://localhost:3000           # сквозной сценарий, 17 шагов на ширине 360 px
python scripts/shots.py http://localhost:3000 out     # снимки всех экранов и проверка вёрстки
```

## Деплой

**Amvera Cloud** (используется для конкурса): в репозитории лежит [amvera.yml](amvera.yml). Создать проект Node.js, добавить бесплатный домен, затем:

```bash
git remote add amvera https://git.<регион>.amvera.ru/<логин>/<проект>
git push amvera main:master
```

Сборка идёт на стороне площадки, файл базы лежит на постоянном диске `/data`.

**Любой сервер с Docker**: `docker build -t deka . && docker run -p 3000:3000 -v deka-data:/data deka`.

**VPS без Docker**: `npm ci --omit=dev && DATA_DIR=/var/lib/deka PORT=3000 node server/index.js` за обратным прокси с HTTPS.

## Стек и почему он такой

| Слой | Решение | Причина |
|---|---|---|
| Сервер | Node.js 24, Express 5 | один процесс, ставится на любой хостинг |
| Данные | SQLite через `node:sqlite` | ноль внешних сервисов; весь SQL в `server/db.js`, переход на PostgreSQL не трогает маршруты |
| Сессии | таблица в БД | сервер без состояния, можно запускать несколько экземпляров за балансировщиком |
| Клиент | ES-модули без сборки, свой CSS | нет цепочки сборки, первый экран открывается быстро даже на слабой сети |
| Пароли | scrypt из `node:crypto` | нативный и быстрый даже на слабом процессоре; первая версия на `bcryptjs` считала хеш 10–30 секунд на тарифе с 0,25 ядра |
| Зависимости | `express`, `helmet` | два пакета, оба MIT |

## Безопасность

1. Кто вы — сервер берёт только из сессии. Идентификатор из адреса или тела запроса игнорируется.
2. Каждый запрос к данным студента отфильтрован по его id. Чужая заявка отвечает 404.
3. Заявки адресуются случайным идентификатором, а не порядковым номером.
4. Пароли хранятся только как хеш scrypt с отдельной солью. Cookie сессии — `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS; в базе лежит SHA-256 от токена.
5. Пять неверных попыток входа за 10 минут — пауза. Попытка засчитывается до проверки пароля, одновременно проверяется не больше шести паролей, подделка IP заголовком не помогает.
6. Изменяющие запросы принимаются только со служебным заголовком и со своего домена (защита от CSRF).
7. Строгий CSP: скрипты только со своего домена. Пользовательский текст экранируется шаблоном `html`.
8. Ключей и паролей сервисов нет ни в коде, ни в браузере: живой LLM в продукт не встроен.

Проверяется тестами `tests/isolation.test.js`, `tests/auth.test.js` и `tests/security.test.js`. Независимое ревью делал Codex: прямой утечки данных не нашёл, шесть его замечаний исправлены — таблица в журнале.

# «Дека» — спецификация прототипа

Рабочее название: **«Дека»** — цифровой деканат в кармане. Концепт для конкурса MGIMO×AI Challenge, адаптирован под ДПИ НГТУ (Дзержинск). Не официальный сервис вуза. Полный текст задания: [ЗАДАНИЕ.md](ЗАДАНИЕ.md).

## 1. Проблема и идея

Учебная жизнь разбросана: расписание на сайте, оценки в другой системе, справка — очередь в деканат, объявления — в чатах. «Дека» отвечает на три вопроса студента за одно касание:

1. **Что у меня сегодня?** Экран «Сегодня»: ближайшая пара, переносы, горящие дедлайны, статус заявок, свежие объявления.
2. **Как у меня дела с учёбой?** Одна фраза-вывод + цифры: долги, средний балл, дисциплины под риском.
3. **Что мне нужно от деканата?** Заявка в три поля, статус как у посылки, переписка с деканатом внутри заявки, электронная справка с кодом проверки вместо очереди.

Разделы связаны: смена статуса заявки → уведомление → карточка на «Сегодня»; перенос пары → отметка в расписании → уведомление; долг в зачётке → кнопка «Подать заявление на пересдачу» с подставленной дисциплиной.

## 2. Роли

- `student` — видит только свои профиль, расписание группы, оценки, заявки, уведомления.
- `staff` — сотрудник деканата: очередь заявок, смена статуса с комментарием, ответ студенту, публикация объявлений, перенос пары. Не видит пароли и не входит от имени студента.

## 3. Стек

| Слой | Решение | Почему |
|---|---|---|
| Сервер | Node.js 24, Express 5, ES-модули | один процесс, ставится на любой VPS/PaaS без Docker |
| Данные | SQLite (`node:sqlite`, встроен в Node), файл в `DATA_DIR` | ноль внешних сервисов; слой `server/db.js` изолирован — замена на PostgreSQL без правки маршрутов |
| Сессии | таблица `sessions` в БД, не память процесса | сервер без состояния: можно запускать несколько экземпляров |
| Пароли | bcrypt (`bcryptjs`, cost 11) | пароль в открытом виде не хранится нигде |
| Клиент | SPA на чистых ES-модулях, без сборки; свой CSS | нет цепочки сборки — нечему сломаться при деплое; быстрый первый экран |
| Тесты | `node --test`, запросы к живому серверу на временной БД | проверяют разделение данных между студентами |

Живой LLM в прототипе нет: ключи ИИ не нужны ни серверу, ни браузеру.

## 4. Безопасность (обязательные правила)

1. Идентификатор пользователя берётся **только из серверной сессии** (`req.user`), никогда из URL, тела запроса или заголовка.
2. Каждый запрос к данным студента содержит `WHERE student_id = ?` с id из сессии. Чужая заявка отвечает `404` (не `403` — не раскрываем, что она существует).
3. Заявки адресуются случайным `public_id` (12 символов), не порядковым номером.
4. Cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, срок 7 дней. В БД хранится SHA-256 от идентификатора сессии.
5. Изменяющие запросы принимаются только с заголовком `X-Requested-With: deka` и совпадающим `Origin` — защита от CSRF.
6. Вход: не более 5 неудачных попыток за 10 минут на пару «логин + IP», затем `429`.
7. Заголовки `helmet`, строгий CSP: скрипты и стили только со своего домена, без inline-скриптов.
8. Весь пользовательский текст экранируется при выводе (шаблонный тег `html` в клиенте).
9. Маршруты `/api/staff/*` доступны только роли `staff`.
10. Секретов в коде нет. Настройки — через переменные окружения (`.env.example`). В `seed/demo-accounts.json` лежат пароли только для локального запуска; пароли стенда для жюри (`seed/demo-accounts.prod.json`) в основную ветку не попадают и уезжают на сервер с веткой деплоя. Смена пароля для демо-аккаунтов отключена, чтобы аккаунт нельзя было «угнать» у жюри.
11. Заголовкам прокси (`X-Forwarded-*`) сервер верит только на площадке. Попытка входа засчитывается до проверки пароля; одновременно считается не больше шести bcrypt; пароли длиннее 72 байт отклоняются.
12. Переписка ограничена: 30 сообщений в час на человека, 200 на заявку. Дата выдачи справки фиксируется один раз.

## 5. API (JSON, префикс `/api`)

| Метод и путь | Назначение |
|---|---|
| `POST /auth/login`, `POST /auth/logout`, `GET /me`, `POST /auth/password` | вход, выход, профиль, смена пароля |
| `GET /home` | сводка «Сегодня» |
| `GET /schedule?from=YYYY-MM-DD&days=N` | расписание с наложенными изменениями |
| `GET /grades` | семестры, дисциплины, контрольные точки, вывод «как дела» |
| `GET /session` | зачёты и экзамены ближайшей сессии |
| `GET /application-types`, `GET/POST /applications`, `GET /applications/:pid`, `POST /applications/:pid/cancel`, `POST /applications/:pid/messages` | заявки студента |
| `GET /notifications`, `POST /notifications/:id/read`, `POST /notifications/read-all` | уведомления |
| `GET /staff/summary`, `GET /staff/applications`, `GET /staff/applications/:pid`, `POST /staff/applications/:pid/status`, `POST /staff/applications/:pid/messages`, `GET/POST /staff/announcements`, `GET /staff/groups`, `POST /staff/schedule-changes` | кабинет сотрудника |
| `GET /verify/:code` | публичная проверка подлинности электронной справки (ФИО замаскировано) |
| `GET /healthz` | проверка живости |

Статусы заявки: `submitted` → `in_progress` → `ready` → `issued`; ветки `rejected`, `cancelled` (студент может отменить, пока `submitted`).

## 6. Экраны

Студент: Вход · Сегодня · Расписание (день/неделя) · Учёба (сводка, семестры, сессия) · Заявки (каталог, форма, карточка со статусом и перепиской) · Уведомления · Профиль.
Сотрудник: Очередь заявок · Карточка заявки · Объявления · Перенос пары.
Мобильная навигация — нижняя панель из 5 вкладок; от 960 px — боковая панель.

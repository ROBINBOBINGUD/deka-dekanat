### Ревью безопасности

Промпт (суть): «Hunt for REAL, exploitable problems… any route where data is selected without the session user id… can an attacker lock the jury out of the demo accounts?.. Do not pad the list: if something is fine, say it is fine».

Вывод Codex: **прямой утечки данных между студентами нет** — профиль, оценки, заявки, переписка и уведомления привязаны к сессии, чужая заявка отвечает 404, `/api/staff/*` закрыты ролью, SQL параметризован, пользовательский текст экранируется. Но шесть мест стоило усилить:

| Серьёзность | Находка | Исправление |
|---|---|---|
| Высокая | Пароли демо-аккаунтов, включая сотрудника, лежат в открытом репозитории: любой читатель мог бы испортить стенд перед показом жюри | Пароли стенда генерируются отдельно (`seed/demo-accounts.prod.json`), в открытый репозиторий не попадают и уезжают на сервер только с веткой деплоя. В репозитории остались пароли для локального запуска |
| Средняя | `trust proxy = 1` при прямом запуске позволяет подделать IP и обойти лимит входа | Заголовкам прокси сервер верит только на площадке (`AMVERA` или `TRUST_PROXY`) |
| Средняя | Лимит проверялся до bcrypt, а попытка записывалась после: параллельные запросы проходили скопом | Попытка засчитывается до проверки пароля; одновременно не больше шести проверок bcrypt; хеш-пустышка считается при запуске |
| Средняя | bcrypt молча отбрасывает всё после 72 байт; вход мог завершиться уже после смены пароля | Пароли длиннее 72 байт отклоняются; сессия выдаётся, только если хеш не изменился; смена пароля и закрытие сеансов — в одной транзакции |
| Средняя | Студент мог «залить» переписку одной заявки | 30 сообщений в час на человека, 200 на заявку, индекс по заявке |
| Низкая | Дата выдачи справки бралась из времени последнего изменения и «плыла» от переписки | Отдельное поле `issued_at`, фиксируется один раз |

После правок: 29 прежних тестов зелёные. Субагент № 5 (Sonnet 5.5) пишет ещё семь тестов именно на эти защиты, с тем же запретом чинить сервер.
